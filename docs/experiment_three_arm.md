# 三臂实验报告

> v0.8 | 2026-07-24 | 三臂实验完成

## 1. 实验问题

**DecisionCoder 的领域模板层和规则路由层对端到端任务成功率产生了多大贡献？** 具体而言：

- H1：规则路由（`_run_rule_routing()` 接线至 Coder）能提高成功率——相比纯 LLM 路由减少模板选择错误。
- H2：领域模板库（EOQ / 需求预测 / 安全库存 / 补货点等 7 个模板）提供完整性标准——相比通用脚手架，模板强制输出完整性（含误差指标、规范命名等）。
- H3：规则路由 + 模板库构成的"增强"与裸 LLM 工具使用基线之间存在可测量的差距。

## 2. 实验设计

### 2.1 三臂

| 臂 | 名称 | 说明 |
|----|------|------|
| **C** | routing_on | DecisionCoder 全量能力：领域模板 + 规则路由接线 + LangGraph 闭环 + Debugger 重试 + HITL 中止 |
| **B** | routing_off | DecisionCoder 减规则路由：同上但设置 `DECISIONCODER_NO_ROUTING=true`，Coder 退回到纯 LLM 自由选择模板 |
| **A** | claude_code | Claude Code 裸用：仓库外隔离空目录，`claude -p` 子进程，无任何 DecisionCoder 框架增强。仅访问 3 个 CSV 数据文件 |

### 2.2 控制变量

- **同一基座模型**：三臂均通过同一本地代理（ccswitch）调用同一后端模型。B/C 臂经 DeepSeek API 接口；A 臂经 Claude Code CLI 接口。代理路由映射确保最终到达同一模型端点。
- **相同任务集**：17 个 Benchmark 任务（BA-01~05 / CG-01~05 / ADV-01~07），query 逐字一致。
- **相同重复**：每任务 3 次运行。B/C 臂 × 2 批次（主批次 + 对抗批次）= 每臂 60 条（BA/CG）；A 臂 × 1 批次 = 每臂 51 条（全部 17 任务）。
- **相同判定算法**：`_keyword_found()` 三臂完全一致（不区分大小写 substring + 浮点数宽松前缀匹配）。
- **判定域差异（已知、文档化）**：A 臂扫描 `claude` 最终答复文本（`result` 字段）；B/C 臂扫描 `execution_result`（stdout）+ `final_report`（Markdown 报告）。

### 2.3 环境配置

| 臂 | 环境 | 关键设置 |
|----|------|---------|
| C (routing_on) | DecisionCoder repo 内 | `DECISIONCODER_NO_ROUTING` 未设置 |
| B (routing_off) | DecisionCoder repo 内 | `DECISIONCODER_NO_ROUTING=true` |
| A (claude_code) | 仓库外 `arm_a_workspace/` | 仅 3 个 CSV；扫描父级目录链无 CLAUDE.md |

B/C 臂共同设置：`DECISIONCODER_HITL_AUTO=1,4`（benchmark 无人值守自动应答）、30s 执行超时。

A 臂正式口径超时 600s（`--timeout-cap 600`），敏感性口径 60s（保留参照）。

## 3. 任务与判定

### 3.1 任务构成

| 类别 | 任务数 | 任务 |
|------|--------|------|
| 数据分析 | 5 | BA-01~05 |
| 代码生成 | 5 | CG-01~05 |
| 对抗（路由鲁棒性） | 5 | ADV-01~05（EOQ 多说法） |
| 对抗（模板外兜底） | 2 | ADV-06（回文）、ADV-07（满减） |

### 3.2 判定标准

主判定（`success` 字段）：`expected_keywords`（结果词）全部 AND 命中 + 无失败否决（`human_feedback == "ABORT"` / `fail_*.md` 存在 / 超时）。

ADV-06/07 因关键词过少（各 2 个）标记 `needs_manual_review=true`，机器判定后必做人工复核。

ADV-07 已在 2026-07-23 终审中裁决为任务设计缺陷（题目未明确满减门槛计算基数），全部 6 条（B/C 各 3 条）和 A 臂 3 条整体退出成功率与一致率分母。

### 3.3 复核口径

全部运行经两轮复核：AI 初审（Claude Code，2026-07-23/24）+ 人类终审（Kimi 辅助裁决）。

三口径：
- **严格口径**（机器判定，不捞回）：JSONL `success` 字段原始值
- **复核后口径**（措辞/机制词假失败捞回）：内容/数值正确、仅缺中英文关键词的运行，经人类终审确认后捞回为成功
- **复核后 + 过程性假失败脚注**（B/C 臂专属，口径三）：CG-05 routing_off run1 中止但实质完成的 Pipeline 8/8 步，严格口径不捞回，以脚注单列其影响

### 4.4 一致率

**机器口径**（`numeric_extractor`，中位数 ±5% 口径）：主批次 routing_on 100%、routing_off 100%；对抗批次 routing_on 85%、routing_off 88%。对抗批次包含 ADV-07（已整体裁决剔除，见 §3.3 与复核日志）等异常单元格。以下为剔除 ADV-07 后的逐任务复核口径：

B/C 臂主批次所有有数值的任务（CG-01~04），3 次重复运行数值偏差在 ±5% 以内——一致率 100%。

A 臂 600s 口径下一致率 100%（BA-01 三值正确 ×3、EOQ=223.61 ×3、CG-03 Z=1.64 ×3、CG-04 ROP=250 ×3）。

对抗批次一致率：B/C 臂 ADV-01~05 一致率 100%（所有 EOQ=223.61）。A 臂 ADV-01~05 一致率 100%。

> 每格 n=3，无显著性检验。机器口径数值取自 Benchmark 批次报告头部；复核口径为逐任务人工核实结果。

## 5. 发现

### F1 — 规则路由层产生确定性贡献（确认 H1）

C − B 差值在严格口径 +5.0pp、复核后口径 +6.7pp。路由关闭（B 臂）的额外失败集中在两类：BA-05 的空壳报告（`run_analysis()` 一行调用、Reporter 未内联子报告结果）和 CG-05 的 `run_pipeline` 函数名幻觉（正确名称为 `run_inventory_pipeline`）。路由开启（C 臂）减少了模板选择错误——确定性匹配取代了 LLM 的猜测。

### F2 — 模板强制完整性标准（确认 H2）

CG-02（需求预测）的 `expected_keywords` 中包含"MAPE"——DecisionCoder 的 `demand_forecast` 模板在计算预测结果的同时自动输出误差评估指标。A 臂三次运行均未计算 MAPE 或任何误差指标——预测数值正确但输出不完整。这"不是能力缺陷，而是模板强制了分析师习惯 vs 自由实现缺少该环节"的质性对照（[review_arm_a_20260724.md §4.1](../results/review_arm_a_20260724.md)）。

### F3 — 价值集中于领域分析任务

ADV-01~06（简单算法/计算任务）复核后三臂均为 100%——无差异。主任务差距（C: 95.0% vs A: 86.7%）集中在：BA-03（图表生成中的 bar/bar_chart 中文命名）、BA-04（Text-to-SQL 模板缺失对 A 臂的偏置）、BA-05（`run_analysis` 一键模板 vs A 臂过度工程化的探索性多轮对话）、CG-02（模板强制 MAPE vs 自由实现缺失）、CG-04（补货点名词缩写 ROP 的中文表述）。

专用性价值集中于**数据读取 + 模板调用 + 输出完整性**的领域分析任务，而非纯算法任务（[review_arm_a_20260724.md §4.4](../results/review_arm_a_20260724.md)）。

### F4 — 数量级成本优势

B/C 臂平均 ~7K tokens / 14s 完成一个任务（模板单次执行），A 臂平均 ~34s（探索性多轮对话）。在"一键分析"类指令下，A 臂触发了具有显著过度工程化的多轮交互（BA-05 run2: 18 turns / 131 行 / 5.5 分钟；run3: 21 turns / 307 行 / 4.8 分钟），而 B/C 臂的 `run_analysis()` 模板约 20s 单发完成。这是两臂行为模式差异的经典表现（[review_arm_a_20260724.md §4.5](../results/review_arm_a_20260724.md)）。

### F5 — 测量学教训

**中文关键词偏置（三臂同病）**：BA-01 "销量"是实验中最高频的措辞假失败（B/C 臂 6 条失败中 5 条、A 臂 2/2 条）。系统使用英文列名 `sales_volume` 是正确的实现选择，但关键词验证器不匹配。BA-03 "bar"——A 臂 3/3 次写"柱状图"未写 "bar"，B/C 臂因走 `bar_chart` 模板命中。

**判定域差异**：A 臂扫描 `claude` 最终答复文本（不含 stdout 中间输出、不含生成的代码文件内容），B/C 臂扫描 `execution_result`（完整 stdout）+ `final_report`。此差异导致 ADV-06 run3（A 臂）的关键词 `palindrome` 存在于代码文件中不在答复文本——正确实现在不同臂的判定下不一致。

**超时截断**：A 臂 60s 口径下 8/51 条超时，成功率 26.7%。600s 后超时问题消除，成功率 53.3%（严格）/ 86.7%（复核后）。

### F6 — 通用脚手架的可取行为

A 臂在工具缺失时的诚实回退是正面发现：BA-04 中 claude 声明 `run_text_to_sql` 不存在并回退到 pandas；CG-04 中声明无 `reorder_point` 模板并回退到标准公式。两次回退后计算结果正确。A 臂"在工具缺失时能诚实声明并给出可替代的正确实现，而非静默忽略或编造假结果"（[review_arm_a_20260724.md §4.6](../results/review_arm_a_20260724.md)）。

### F7 — 迭代清单

从复核过程中识别的改进项（详见 [CLAUDE.md 已知问题](../CLAUDE.md)）：

1. Reporter 提示词增加"若分析委托给子报告，必须将子报告关键结果内联"
2. 归档范围扩展：stdout、生成代码、生成文件按 run 归档
3. 验证器扫描域文档化（A 臂 vs B/C 臂的判定文本来源）
4. manifest 改 arm_sequence 数组以完整记录双臂信息
5. `expected_keywords` 补充等效中文关键词以降低措辞假失败率
6. `_find_generated_files` 按 task_id 过滤以避免跨任务文件混淆

## 6. 局限

1. **每格 n=3**：重复次数少，无统计检验（无置信区间、无 p 值），仅报告点估计。结论为质性方向性，非统计推断。
2. **A 臂判定域差异**：A 臂仅扫描最终答复，不扫描 stdout——相当于 B/C 臂的关键词匹配更宽松（额外 stdout 文本）。严格意义下 A 臂与 B/C 臂的 success 字段不完全可比。
3. **单批次 A 臂**：B/C 臂有两批次（主/对抗），各 60 条；A 臂仅一批次，主任务 30 条——A 臂的方差估计更粗糙。
4. **A 臂接口差异**：A 臂经 Claude Code CLI（多轮对话），B/C 臂经 LangChain/DeepSeek API（单次 invoke + 最多 2 次 retry）。接口差异本身就构成实验效应，非纯粹的"模板/路由 vs 裸用"对比。
5. **无随机化**：任务固定，无随机顺序，未控制顺序效应。
6. **任务集偏置**：10+7 任务均由项目作者设计，偏向领域模板覆盖而不是均匀采样真实用户需求。BA-04（Text-to-SQL 专有工具）和 CG-02（模板内嵌误差组件）对 A 臂存在结构性偏置。
